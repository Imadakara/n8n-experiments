# Фикс: тумблер "Available in MCP" не сохраняется

Дата: 2026-07-07
Связанный баг: n8n-io/n8n **#25987** — "Available in MCP toggle not persisting"

## Симптомы (как воспроизводилось)

Тумблер "Available in MCP" можно включить (запрос уходит, ошибки нет), но состояние
сбрасывается обратно на выключено при любом из действий:

- переход в сам воркфлоу из списка;
- открытие настроек воркфлоу заново;
- обновление страницы (F5).

Из-за этого `search_workflows` в MCP-инструментах n8n всегда возвращал пустой список,
даже если тестовый воркфлоу был опубликован и физически виден в UI.

## Корневая причина

В `workflow.service.ts` (`WorkflowService.update`) есть механизм: если у **активного
(опубликованного)** воркфлоу меняются `settings`, сервис автоматически прогоняет его
через цикл деактивация → реактивация (`activateWorkflow`), чтобы применить новые
настройки к уже работающим триггерам/вебхукам.

Проблема в том, что это срабатывает на **любое** изменение `settings`, включая
`availableInMCP` — а этот флаг вообще не влияет на поведение триггеров, это чисто
метаданные для MCP-тулинга.

Если реактивация по любой причине падает (конфликт вебхука, ошибка external hook и
т.п.), метод `_addToActiveWorkflowManager` откатывает воркфлоу в
`active: false, activeVersionId: null` — то есть воркфлоу **тихо снимается с
публикации**. А поскольку MCP-доступ разрешён только для опубликованных воркфлоу,
тумблер в UI после этого выглядит выключенным/недоступным при любом обновлении данных
(переход в воркфлоу, открытие настроек, F5) — именно то поведение, которое было
описано в баг-репорте.

Сам флаг `availableInMCP` при этом физически мог оставаться `true` в БД — сбрасывалась
не сама настройка, а публикация воркфлоу, которая требуется для того, чтобы MCP-доступ
вообще был виден/доступен.

## Побочная находка

Эндпоинт `PATCH /mcp/workflows/:workflowId/toggle-access` не возвращал `checksum` в
ответе (в отличие от общего `PATCH /workflows/:id`). Из-за этого после переключения
тумблера через список воркфлоу (`WorkflowCard.vue`) чек-сумма воркфлоу в сторе
редактора (`workflowsStore.workflowChecksum`) оставалась устаревшей — это могло
привести к отдельной ошибке "workflow locked / conflict" при следующем сохранении в
той же сессии редактора.

## Что исправлено

1. `availableInMCP` исключён из сравнения, которое решает, нужна ли реактивация
   воркфлоу. Настройка по-прежнему нормально сохраняется в БД, просто больше не может
   утащить за собой весь воркфлоу в offline.
2. Эндпоинт `toggle-access` теперь возвращает `checksum`, фронтенд сохраняет его в
   стор — чек-сумма больше не протухает после переключения тумблера из списка.

## Затронутые файлы

### Исходники (репозиторий `n8n-fork`, ветка `local-2.8.4`)

| Файл | Изменение |
|---|---|
| `packages/cli/src/workflows/workflow.service.ts` | Добавлена константа `SETTINGS_KEYS_EXCLUDED_FROM_REACTIVATION = ['availableInMCP']`; `settingsChanged` теперь сравнивает `settings` без учёта этого ключа (через `lodash/omit`) |
| `packages/cli/src/modules/mcp/mcp.settings.controller.ts` | `toggleWorkflowMCPAccess` теперь дополнительно возвращает `checksum` (через `calculateWorkflowChecksum` из `n8n-workflow`) |
| `packages/frontend/editor-ui/src/features/ai/mcpAccess/mcp.api.ts` | Тип ответа `toggleWorkflowMcpAccessApi` дополнен полем `checksum` |
| `packages/frontend/editor-ui/src/features/ai/mcpAccess/mcp.store.ts` | `toggleWorkflowMcpAccess` передаёт полученный `checksum` в `workflowsStore.setWorkflowVersionData(...)` |

### Скомпилированные файлы (глобальная установка `n8n`, `C:\Users\PC\AppData\Roaming\npm\node_modules\n8n`)

Пропатчены вручную для тестирования без пересборки монорепы — зеркалируют изменения
из `workflow.service.ts` и `mcp.settings.controller.ts` выше:

| Файл | Изменение |
|---|---|
| `dist/workflows/workflow.service.js` | добавлен `require("lodash/omit")` + та же константа-исключение и патч логики `settingsChanged` |
| `dist/modules/mcp/mcp.settings.controller.js` | добавлен `require("n8n-workflow")` + возврат `checksum` в ответе |

Фронтенд-часть (`mcp.api.ts` / `mcp.store.ts`) в скомпилированном виде **не патчилась** —
это единый минифицированный бандл редактора, вручную его трогать нецелесообразно.
Это не критично: причина основного бага — полностью на бэкенде.

⚠️ Патч скомпилированных файлов переживёт только до следующего
`npm install -g n8n` / обновления — при переустановке пакета правки в `dist/` будут
затёрты. Для постоянного фикса нужно смёржить изменения в исходниках и пересобрать
проект штатным способом.

## Как проверить

1. Перезапустить процесс `n8n` (`n8n start`) — пересборка не требуется, изменения уже
   в скомпилированных файлах.
2. Включить "Available in MCP" на опубликованном воркфлоу с поддерживаемым триггером.
3. Зайти в настройки воркфлоу заново или обновить страницу (F5) — тумблер должен
   остаться включённым.
4. Проверить, что `search_workflows` через MCP теперь видит воркфлоу.
