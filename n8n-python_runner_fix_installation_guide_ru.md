# Перенос фикса Windows Python Runner в новый клон n8n

## Требования

Перед началом убедитесь, что используется именно следующая конфигурация:

-   **Node.js 20.x**
-   **n8n release/2.8.4**

> Данный фикс разрабатывался и тестировался на **релизной ветке
> `release/2.8.4`**. Более новые версии n8n (например, 2.29.x) имеют
> отличия в кодовой базе и требуют отдельной адаптации. Также
> современные версии n8n требуют Node.js 22+, поэтому для
> воспроизведения данной инструкции рекомендуется использовать **Node.js
> 20**.

------------------------------------------------------------------------

## Исходная ситуация

Есть два репозитория:

1.  **n8n-experiments** --- отдельный репозиторий, содержащий только
    изменённые файлы Python Runner.
2.  **n8n-fork** --- свежий клон/форк n8n (ветка `release/2.8.4`), в
    который необходимо перенести фикс.

Истории репозиториев независимы, поэтому использовать `merge` или
`cherry-pick` не нужно.

``` bash
cd C:\Users\PC\Documents\Development\n8n-fork
```

## 2. Добавить репозиторий с фиксом


Проверить:

``` bash

```

## 3. Получить информацию о ветках

``` bash
git fetch fix
```

При необходимости посмотреть доступные ветки:

``` bash

```

------------------------------------------------------------------------

## 4. Скопировать файлы с фиксом

``` bash
git checkout fix/0726/internal_python_windows-fix -- packages/@n8n/task-runner-python
```

Эта команда:

-   не переключает ветку;
-   не делает merge;
-   не переносит историю Git;
-   не создаёт конфликтов.

Она просто заменяет каталог `packages/@n8n/task-runner-python` его
содержимым из указанной ветки другого репозитория.

## 7. Создать Python virtual environment

Перейти в каталог Python Runner:

```powershell
cd packages/@n8n/task-runner-python
```

Создать виртуальное окружение и установить все зависимости проекта:

```powershell
python -m uv sync --group dev
```

> Не создавайте `.venv` вручную.
>
> Команда `python -m uv sync --group dev` самостоятельно:
>
> - выбирает совместимый Python-интерпретатор;
> - создаёт `.venv`;
> - устанавливает все зависимости;
> - подготавливает Runner к запуску.

После завершения рекомендуется проверить:

```powershell
Test-Path .\.venv\Scripts\python.exe
```

Ожидаемый результат:

```text
True
```

------------------------------------------------------------------------

## 8. Установить глобальную версию n8n

Для разработки Python Runner не требуется собирать весь monorepo.

Используется обычная глобальная установка:

```powershell
npm install -g n8n
```

После установки файл

```
C:\Users\<User>\AppData\Roaming\npm\node_modules\n8n\dist\task-runners\task-runner-process-py.js
```

необходимо изменить вручную.

> Важно:
>
> Этот файл находится **вне Git-репозитория**.
>
> Изменения не попадают в коммиты и должны выполняться отдельно после установки новой глобальной версии `n8n`.

------------------------------------------------------------------------

## 9. Настроить использование локального Python Runner

```
C:\Users\<User>\AppData\Roaming\npm\node_modules\n8n\dist\task-runners\task-runner-process-py.js
```

### Изменить `startProcess()`

Заменить

```js
const pythonDir = node_path.default.join(__dirname, '../../../@n8n/task-runner-python');
```

на

```js
const pythonDir =
    process.env.N8N_LOCAL_PYTHON_RUNNER ??
    node_path.default.join(__dirname, '../../../@n8n/task-runner-python');

this.logger.info(`Using Python runner from: ${pythonDir}`);
```

---

### Изменить `getVenvPath()`

Полностью заменить метод:

```js
static getVenvPath() {
    const pythonDir =
        process.env.N8N_LOCAL_PYTHON_RUNNER ??
        node_path.default.join(__dirname, '../../../@n8n/task-runner-python');

    return node_path.default.join(
        pythonDir,
        process.platform === 'win32'
            ? '.venv/Scripts/python.exe'
            : '.venv/bin/python',
    );
}
```

Данные изменения дают две возможности:

- использовать локальный Runner через переменную окружения;
- корректно запускать Windows virtual environment (`.venv\Scripts\python.exe`).

------------------------------------------------------------------------

## 10. Запуск n8n

Перед каждым запуском необходимо указать путь к локальному Runner:

```powershell
$env:N8N_LOCAL_PYTHON_RUNNER="C:\Users\PC\Documents\Development\n8n-fork\packages\@n8n\task-runner-python"
```

После этого запуск выполняется обычной командой:

```powershell
n8n
```

При успешной настройке в логах появится сообщение:

```text
Using Python runner from:
C:\Users\PC\Documents\Development\n8n-fork\packages\@n8n\task-runner-python
```

Это означает, что глобально установленный `n8n` использует локальный `task-runner-python` из репозитория.

Теперь любые изменения файлов внутри

```
packages/@n8n/task-runner-python
```

сразу используются при следующем запуске `n8n` без копирования файлов и без пересборки всего monorepo.

# Почему используется именно такая схема

На первый взгляд может показаться, что логичнее запускать `n8n` непосредственно из исходников репозитория. Однако для версии **2.8.4** это оказалось менее удобно.

Во время исследования было выбрано другое решение:

- использовать обычную глобальную установку `n8n` через `npm`;
- разрабатывать только `task-runner-python` в локальном Git-репозитории.

Для этого глобальный `n8n` был слегка модифицирован: вместо жёстко заданного пути к встроенному Python Runner он умеет использовать путь из переменной окружения `N8N_LOCAL_PYTHON_RUNNER`.

В результате:

- не нужно разворачивать Docker;
- не требуется собирать весь monorepo после каждого изменения;
- не требуется копировать файлы Python Runner в установленный `n8n`;
- любые изменения в `packages/@n8n/task-runner-python` начинают использоваться сразу после следующего запуска `n8n`;
- вся разработка Python Runner ведётся в обычном Git-репозитории со своей историей изменений.

По сути, глобально установленный `n8n` используется только как исполняемое приложение, а весь Python Runner загружается непосредственно из локального репозитория разработчика.
